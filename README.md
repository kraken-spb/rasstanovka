# Расстановка бригад

Фильтры расстановки, поиск, Regex, выбранная дата и группировка сохраняются в учётной записи и восстанавливаются после обновления страницы. Кнопка «Сбросить фильтры» снимает поиск, фильтры участка, категории, автора, смены, актуальности и «Не расставленные», а также фильтр перехода из сводной. Рабочая дата, группировка и настройки столбцов сохраняются. Сброс не изменяет назначения сотрудников.

Защищённый веб-сервис для назначения сотрудников на объекты и подобъекты по датам и сменам. В репозитории находится только демонстрационный `seed.example.json` с вымышленными данными. Рабочая база, персональные данные, выгрузки и секреты в Git не включаются.

## Запуск в Docker

1. Скопируйте `.env.example` в `.env`.
2. Замените `ADMIN_PASSWORD` и `SECRET_KEY` на собственные значения. Для `SECRET_KEY` используйте случайную строку длиной не менее 32 символов.
3. Запустите `docker compose up --build -d`.
4. Откройте `http://localhost:8088`.

Данные хранятся в именованном Docker-томе `placement_data` и сохраняются после перезапуска контейнера.

Новая база в Docker заполняется демонстрационными данными из `seed.example.json`. Для локального запуска и тестов сначала скопируйте его в `seed.json` (PowerShell: `Copy-Item seed.example.json seed.json`), если локального файла ещё нет. Не заменяйте существующий рабочий `seed.json`. Собственные данные загружайте через импорт приложения. Существующая база при пересборке не перезаписывается.

## Возможности

Основной экран «Расстановка» — плоская таблица из 13 столбцов, включая «Смена», сгруппированная по номерам бригад из импортированной численности. Бригады можно сворачивать и разворачивать, как группы в Excel. На компьютере таблица прокручивается внутри своей области; на телефоне строки показаны на всю ширину с кнопкой «Все поля». Сверху доступны выбор строительного участка, поиск, фильтры смен и «Без назначения». Поиск проверяет ФИО, табельный номер, должность, категорию, участок, бригаду и место работы. Переключатель Regex включает регулярные выражения без учёта регистра: например, `№(814|815)_` находит две бригады. При ошибке шаблона показывается пояснение и сохраняется предыдущий результат.

Смена («День» или «Ночь») сохраняется для каждого сотрудника на выбранную дату даже без назначения подобъекта. По умолчанию используется 1 смена (день), если сотруднику ещё не задана смена и нет существующего назначения. В строке сотрудника выбор сохраняется сразу; в строке «Вся бригада» выберите смену и нажмите «Всем». Действие применяется ко всей импортированной бригаде, включая скрытых фильтром сотрудников. Изменение смены переносит существующее место работы и обновляет дневной/ночной факт сводки. Общее назначение подобъекта сохраняет индивидуальные смены сотрудников. Единственное существующее назначение определяет смену автоматически; несколько старых назначений за сутки не объединяются и не удаляются — их нужно уточнить в разделе «Состав бригад». Изменение всей бригады выполняется одной транзакцией с проверкой актуальности всех строк.

В разделе импорта администратор загружает XLSX и сначала проверяет результат. Используется только лист «Явка»: подразделения «Строительно-монтажный участок», квалификация «Рабочие», категории ГДЛР без водителей, машинистов и вспомогательных. Профессия не подменяет категорию: «Прочие основные рабочие» остаются в расстановке. Номер бригады берётся из именованного столбца либо из незаголовленного столбца Y данного формата. Пустое значение и ошибка `#N/A` показываются группой «Бригада не указана».

«Компания подрядчик» заполняется значением «ЛГСС». Для цифрового табельного номера «Организация-работодатель» также равна «ЛГСС»; для других номеров остаётся пустой. В заголовке «Таб. № с префиксом» сохраняется исходное название, к значениям префикс не добавляется. Категория и должность берутся из файла; «Профессия ГСП» пока пустая.

ФИО линейного ИТР и бригадира задаются для всей бригады в последних двух ячейках строки «Вся бригада» или через кнопку «Ответственные» у её заголовка. Нажатие на соответствующее ФИО в строке сотрудника позволяет исправить только это поле у одного человека. Кнопка «Как у бригады» возвращает общее значение выбранного поля, сохраняя корректировку второго. Последующие изменения общих ФИО не стирают построчные исправления. Доступ учётной записи прораба назначается отдельно через «Управление».

Оба поля поддерживают поиск с Regex по всем сотрудникам листа «Явка», включая ИТР, исключённых из расстановки рабочих. Поиск проверяет ФИО, табельный номер, должность, участок и исходную бригаду; например, `^Прораб$|Мастер строительных` или `^58254$`. Выберите конкретную запись из результатов и нажмите «Сохранить». Сохраняются полное ФИО и ссылка на выбранного сотрудника из файла; привязка к бригаде действует между датами и сменами. Однофамильцы показаны отдельными строками с табельным номером и должностью. Режим «Вручную» оставляет возможность текстовой корректировки без связи с записью файла. При загрузке следующего файла существующие привязки сохраняются и автоматически по совпадению ФИО не заменяются.

При повторном импорте ранее загруженного файла недостающий справочник ФИО дополняется после резервного копирования, без повторного заполнения составов и назначений. Сам справочник не добавляет ИТР в численность рабочих.

Объект («Группа подобъектов») и подобъект выбираются выпадающими списками прямо в ячейках. Выбор объекта только ограничивает список подобъектов; выбор подобъекта в строке сотрудника автоматически сохраняет его назначение. Строка «Вся бригада» под заголовком группы позволяет выбрать то же место для всей бригады и применить его одной кнопкой. Эта операция охватывает всех сотрудников бригады из импортированной численности, включая скрытых текущим фильтром; рядом показано их количество. Затем можно отдельно изменить назначение любого сотрудника. Пункт «Без назначения» снимает существующее назначение. Дата и смена входят в назначение. Проверки двойного назначения и изменений в другом окне действуют для этого экрана так же, как для состава бригады.

Перед применением импорта автоматически создаётся согласованная резервная копия SQLite в каталоге `data/backups`. Повтор того же файла не создаёт дубли. Несовпадение ФИО при одинаковом табельном номере и перемещение из другой бригады блокируют импорт для ручной проверки. Старые сотрудники, составы и назначения не удаляются. Таблица показывает сотрудников последнего применённого импорта, а созданные им бригады сначала закреплены за импортировавшим администратором. Назначьте доступ прорабам в разделе «Управление».

Для локального импорта из командной строки используйте `python tools/import_staffing.py "путь.xlsx"` для проверки и тот же вызов с `--apply` для применения в настроенную базу. Перед обновлением схемы приложения также требуется резервная копия базы, описанная ниже.

- роли администратора, прораба и пользователя только для просмотра;
- выдача, отключение учётных записей и смена паролей;
- подбор сотрудников по ФИО, табельному номеру, профессии и организации;
- привязка нескольких бригад к прорабу, постоянный состав каждой бригады;
- дата задаётся для таблицы, смена — каждому сотруднику или всей бригаде;
- массовое назначение: отметить сотрудников и выбрать подобъект;
- выбор места работы прямо на странице, без диалога: отметить людей в составе и нажать подобъект; объект слева фильтрует подобъекты справа, поиск в каждой колонке отдельно;
- защита от двойного назначения сотрудника в одну дату и смену;
- сводная таблица: объекты → подобъекты → организации слева, даты справа; строки «План» / «Факт»;
- режимы сводки «День / ночь», «Всего», «День / ночь / всего»;
- тумблер «Только с планом или фактом» скрывает пустые строки сводки за выбранный период, сохраняя иерархию; заданный план 0 тоже отображается;
- отдельная вкладка плана: один суточный план на подобъект, ввод числа непосредственно в ячейку;
- адаптивный интерфейс для телефона, планшета и компьютера.

Администратор сначала выдаёт прорабу доступ и создаёт его бригады в разделе «Управление». Прораб видит только свои бригады и набирает их из списка сотрудников. Состав сохраняется между датами; удаление из состава не удаляет историю расстановки. Если сотрудника переводят между бригадами в течение смены, сначала снимите его место работы в исходной бригаде на эту дату.

План задаётся целиком на сутки, без искусственного распределения по сменам. В сводке он занимает общую ячейку над дневным и ночным фактом. Пустая ячейка означает отсутствие плана; ноль означает, что люди не требуются. «Всего» в факте — сумма дневных и ночных назначений, не количество уникальных людей за сутки. Итоги объектов суммируют заданные планы подобъектов.

Ввод плана сохраняется по Enter, Tab или выходу из ячейки. Изменение одной ячейки в двух окнах проверяется по версии: чужие изменения не перезаписываются молча. На телефоне таблица прокручивается внутри своей области, структура слева закреплена.

## Обновление и проверка

Перед обновлением сделайте согласованную резервную копию SQLite через `sqlite3.Connection.backup`. Затем выполните `docker compose up --build -d`. Существующие расстановки, пользователи и справочники сохраняются; старые посменные планы однократно суммируются в суточные. Бригады не создаются автоматически по предположениям об их составе.

```powershell
python -m unittest discover -s tests -v
python tools/check_utf8.py
```

Для изолированной проверки интерфейса: `python tools/ui_preview.py` поднимает временную базу на `http://127.0.0.1:18088`. Только в этом тестовом режиме доступны `admin` и `foreman` с паролем `ui-test-password-123`; рабочая база не используется. Для доступа не только на локальном компьютере настройте HTTPS и `COOKIE_SECURE=true`.

## Обновление справочников из Excel

```powershell
python tools/import_excel.py "C:\путь\к\Расстановка.xlsx" seed.json
```

Новый `seed.json` применяется только при первом создании пустой базы данных. Существующие рабочие данные автоматически не перезаписываются.


### Супер-администратор и справочники

Роль `super_admin` включает права администратора и исключительное право создавать, переименовывать и отключать записи справочников ГДТЛР, подрядчиков, групп подобъектов и подобъектов. Обычный администратор видит справочники только для чтения и по-прежнему выбирает существующие записи в расстановке. Импорт явки, план и управление обычными пользователями остаются доступны администратору.

Только супер-администратор может назначать эту роль и менять ФИО, пароль или состояние другой учётной записи супер-администратора. Последнего действующего супер-администратора нельзя понизить или отключить.

Первого супер-администратора назначают явно из существующих активных администраторов:

```powershell
docker compose exec -T placement python tools/promote_super_admin.py --username ЛОГИН
```

Начальная учётная запись из `ADMIN_USERNAME` получает роль администратора; автоматического повышения существующих пользователей при запуске нет. Перед миграцией таблицы пользователей и перед повышением роли создаётся SQLite-копия в каталоге `backups` рядом с базой. Идентификаторы, пароли, остальные роли и ссылки сохраняются. Повторное назначение тому же пользователю безопасно и ничего не меняет. После назначения обновите страницу; повторный вход не требуется.


### Активность пользователей в дашборде

Администраторы и супер-администраторы видят блок «Активность пользователей»: число успешных входов за выбранную дату, число вошедших пользователей, количество пользователей онлайн и последнюю дату/время входа каждой учётной записи. Даты и время — московские. Повторный успешный вход считается отдельно; неверный пароль, обновление страницы и подтверждение присутствия не увеличивают счётчик.

Открытая видимая вкладка подтверждает присутствие раз в минуту. «Онлайн» означает действующую сессию с подтверждением за последние 3 минуты; закрытие или длительное сворачивание всех вкладок переводит пользователя в «Не в сети» по истечении этого срока. Явный выход завершает соответствующую сессию сразу, другие открытые сессии пользователя учитываются отдельно. Статус всегда относится к текущему моменту, даже при просмотре прошлой даты.

Учёт начинается с установки обновления. Для более ранних дат показано отсутствие данных, для первого дня — пометка о неполных сутках. Уже открытые сессии получают статус присутствия после обновления страницы, но не считаются новым входом. Пароли и токены сессий в открытом виде в статистике не сохраняются.


### Массовое изменение бригады

В «Расстановке» раскройте группу, отметьте нужных сотрудников и в общей строке выберите «Бригада выбранных», затем нажмите «Задать бригаду». Как и изменение подрядчика, перевод применяется только к отмеченным сотрудникам текущей группы, включая отмеченных, скрытых фильтром. Доступны группировки по бригадам и по линейному ИТР.

Меняется текущий состав бригад. Сохранённые назначения на даты, смены, явка, выполняемые работы и индивидуальные ответственные сохраняются. Ответственные без индивидуальной корректировки наследуются из новой бригады. Прораб переводит только между своими бригадами; администратор и супер-администратор — между доступными действующими бригадами. Состав выбранных сотрудников и данные новой бригады проверяются перед сохранением; при конфликте вся операция отменяется. После перевода расстановка перезагружается без повторного переноса данных предыдущего дня.
