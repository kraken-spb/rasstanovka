# Отчёты по расстановке в Telegram

Бот отправляет PDF только в личный чат после привязки к активной учётной записи сайта. Права по СМУ проверяются при каждом запросе и перед отправкой файла. Неявки учитываются отдельно. Расчёт и PDF используют те же функции, что и раздел «Отчёт по расстановке».

## Подключение

1. Создайте отдельного бота в [@BotFather](https://t.me/BotFather) командой `/newbot` и получите токен.
2. Войдите на сайт как супер-администратор. Откройте «Сводная таблица → Отчёт по расстановке → Telegram».
3. Вставьте токен в защищённое поле «Токен бота» и нажмите «Подключить бота».
4. Нажмите «Привязать мой Telegram», откройте персональную ссылку в своём Telegram и нажмите «Старт». Ссылка одноразовая, действует 10 минут. Не пересылайте её другим людям.
5. Нажмите «Проверить подключение» на сайте. Бот должен отображаться как работающий, Telegram — как привязанный.

Каждый пользователь сайта привязывает свой Telegram отдельно. Деактивация учётной записи закрывает получение отчётов. Отключить привязку можно на сайте либо командой `/unlink`.

## Запросы

- `/report` — сводный PDF за сегодня по Москве.
- `/report вчера` — сводка за предыдущий день.
- `/report 13.09.2026 ППС15 Электромонтажник` — выбранная дата, ППС и точное название ГДЛР.
- `/report_full 2026-09-13 ППС19` — PDF со списками ФИО.
- `/categories` — доступные названия категорий.
- `/report 13.09.2026 без_ппс без_категории` — пустые значения полей.
- `/help` — справка и кнопки быстрых запросов.

Категория может содержать пробелы. `все_ппс` позволяет указать категорию без ограничения по ППС.

## Эксплуатация

Сервис `telegram` в Docker Compose использует тот же образ и том базы, что и сайт. Входящие запросы забираются через long polling, публичный webhook не требуется. Бот с уже настроенным webhook не подключается, чтобы не нарушить работу другой интеграции.

Токен записывается в файл `telegram.env` рядом с SQLite-базой, внутри рабочего тома, с правами `0600`. Он не хранится в SQLite, не возвращается API и не выводится в логи. Копирование SQLite-базы не включает этот файл: для переноса на новый сервер повторно подключите бота. Не добавляйте рабочий токен в Git или сообщения задачи.

Без токена сервис ожидает подключения. После сохранения токена начинает получать команды автоматически. Проверка `python telegram_worker.py --healthcheck` контролирует свежесть получения обновлений. Отдельная файловая блокировка допускает только один обработчик на томе.

Идентификаторы запросов и смещение Telegram хранятся в SQLite. Повторно доставленный запрос не отправляет файл ещё раз. Если процесс оборвался во время отправки или Telegram не подтвердил результат, повторите команду новым сообщением, если файл не получен. Автоматической рассылки нет.
