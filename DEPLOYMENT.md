# Размещение report-bi на VPS

Сайт опубликован 13 сентября 2026 года: https://report-bi.ru. VPS: `186.246.2.210`, каталог `/opt/report-bi`, контейнер `report-bi-placement-1`. Вход работает с перенесённой учётной записью. Caddy выпустил сертификат Let's Encrypt и обслуживает HTTPS с перенаправлением HTTP.

При первом переносе сохранены 1243 сотрудника, 79 бригад, 1232 привязки к бригадам, 50 назначений, 3 суточных плана и 1 учётная запись. Проверены целостность SQLite, внешние ключи и совпадение количества строк всех 16 таблиц. Локальная резервная копия: `backups/report-bi-vps-20260913T022054Z.sqlite3`; копия на VPS: `/opt/report-bi/staging/placement.sqlite3`. Резервная копия общего прокси: `/opt/report-bi/backups/Caddyfile-before-20260913T022318Z`.

Для общего VPS используется отдельный проект Docker Compose `report-bi` и внешний прокси Caddy в сети `myberries_net`. Приложение не публикует порт на сервере; вход доступен через HTTPS и обычную авторизацию сайта.

## Файлы и запуск

Рабочий каталог: `/opt/report-bi`. Перед запуском разместите там исходные файлы и отдельный `.env` с `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SECRET_KEY`. Файл окружения должен иметь права `600` и не должен попадать в архив исходников. Защищённые cookie включены в `compose.production.yaml`.

```sh
docker compose --env-file .env -f compose.production.yaml config --quiet
docker compose --env-file .env -f compose.production.yaml build
docker compose --env-file .env -f compose.production.yaml up -d
```

## Данные

Для переноса существующего сайта нужна согласованная копия SQLite через `sqlite3.Connection.backup`. Она сохраняет сотрудников, бригады, пользователей, планы и расстановку. Не копируйте файл работающей базы обычной файловой командой.

До первого запуска восстановите копию в том `report-bi_placement_data` по пути `placement.db`, назначив владельца, под которым работает приложение. Если том уже содержит базу, сначала остановите изменение данных, сделайте резервную копию и согласуйте замену. После переноса сравните число строк основных таблиц и выполните `PRAGMA integrity_check`.

Локальная база и база VPS после переноса независимы. Рабочие изменения после перехода следует вносить на опубликованном сайте.

## Домен и HTTPS

Нужен полный домен, направленный A-записью на IPv4 VPS. AAAA-запись должна соответствовать доступному IPv6 этого же сервера либо отсутствовать.

В существующий Caddyfile добавляется отдельный блок для подтверждённого домена:

```caddyfile
report-bi.ru {
    encode zstd gzip
    reverse_proxy report-bi-placement:8000
}
```

Этот блок уже применён в `/opt/myberries/shop/Caddyfile`; повторно добавлять его не нужно. Перед последующими изменениями сохраните резервную копию Caddyfile, проверьте конфигурацию через `caddy validate` и примените её через `caddy reload`. Существующие блоки других сайтов сохраняются.

## Проверка

Проверьте HTTPS, перенаправление HTTP на HTTPS, вход в существующую учётную запись, раздел «Сотрудники», недоступность API без авторизации и состояние `/health`. Сравните переданные файлы по SHA-256. После обновления проверьте также доступность соседних сайтов на общем прокси.
